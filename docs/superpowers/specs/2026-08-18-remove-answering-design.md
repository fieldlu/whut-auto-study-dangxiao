# 刷课脚本瘦身设计

- 日期：2026-08-18
- 范围：`WUT网上党校 全能助手.user.js` 及仓库配套文件
- 目标：彻底移除答题相关能力，仅保留并整理自动刷课能力。

## 背景

当前主用户脚本同时包含课程自动播放与题库/AI答题两套职责，导致脚本体积大、权限多、维护边界不清。仓库还包含题库提取脚本、题库合并脚本和答案数据文件。

## 方案

### 方案 A：仅关闭答题入口
保留题库和答案代码，但把 UI 和自动答题开关关闭。

- 优点：改动小，未来可快速恢复。
- 缺点：答题代码、AI API 权限和答案捕获逻辑仍然存在，不符合“去除答题功能”。

### 方案 B：主脚本拆成刷课版，并删除答题配套文件（推荐）

- 删除主脚本中的题库、云端查答案、AI Provider、自动填充/提交、答案捕获和题目网络拦截代码。
- 清理题库专用 GM 权限、AI API `@connect` 权限与相关配置。
- 删除独立题库提取脚本、题库合并脚本和 `qbank/` 数据文件。
- 更新脚本元数据、README 和 CHANGELOG，明确仓库职责是刷课。
- 保留课程列表扫描、视频接管、断点续播、进度上报、进度看门狗、真人模拟、自动跳课和状态面板。

### 方案 C：拆分成两个仓库/脚本
把刷课和答题拆成两个独立项目。

- 优点：边界最清晰。
- 缺点：超出当前需求，会保留答题能力并增加维护成本。

## 选定设计

采用方案 B。主脚本以 `init()` 为边界：保留其前面的课程自动化模块以及课程初始化逻辑，移除其后的完整题库模块；同时把面板中的题库/AI控件和统计字段改为课程相关信息，避免残留无效按钮、状态变量或权限声明。

### 保留的课程功能

1. 培训班课程列表扫描与状态渲染。
2. 自动进入未完成课程、视频自动播放、断点续播和课程完成后跳转。
3. 进度保存/监控与卡死恢复。
4. 真人模拟交互与视频事件接管。
5. 面板日志、当前课程、总体课程进度和视频进度展示。

### 移除的答题功能

1. 本地/云端题库读写、同步、查询和导出。
2. AI Provider、API Key、模型调用和 AI 兜底。
3. 题目解析、答案填充、答案提交和自动答题循环。
4. 交卷后答案捕获、结果扫描、题库上传。
5. XHR/Fetch 题目数据拦截器。
6. 独立题库脚本、题库合并脚本及题库 JSON 数据。

## 验收标准

- 主用户脚本可通过 JavaScript 语法检查。
- 主用户脚本中不再出现答题/题库/AI逻辑和 AI API 域名。
- 主用户脚本元数据仅保留刷课所需权限。
- README/CHANGELOG 与实际功能一致。
- 课程相关函数和关键字符串仍存在，且仓库无独立答题脚本或题库数据。
- Git diff 只包含本次范围内的清理和文档更新。
